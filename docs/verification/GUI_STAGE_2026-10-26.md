# 原生 QQ Settings GUI 隔离验收（2026-10-26）

本记录仅覆盖当前 GUI 阶段，不代表 QQ v1.0 最终验收。测试使用官方 DSH Desktop 0.2.1-rc.3 的隔离 Profile、插件 `0.1.0-qa.33`、合成 bot/群/私聊 ID；`connect: false`，未连接 NapCat 或真实 QQ。

## 代码与包

- `npm run build` 成功生成随包 `lib/client.js`。
- `npm test`：95/95 通过，覆盖客户端构建、草稿、Owner 限制、HTTP 权限和现有 QQ 核心回归。
- 包经官方 Plugin Manager 安装后，原生设置侧栏出现 `Amadeus QQ`，无须独立网页或手工 JSON 页面。

## 真实 Desktop GUI 操作

- 经本地 DSH Owner 会话打开页面，显示两个合成 Scene、五级模式、每项能力 inherit/allow/deny 和有效权限。普通群的 Owner Agent 选项禁用，已配置 Owner 私聊可选。
- 在合成群选择 Enhanced 并将 `qq.send` 设为 deny，GUI 保存成功；服务端 revision 从 0 变为 1，页面显示有效拒绝。
- 另一个经 Owner 验证的请求将同一 Scene revision 增至 2；旧 GUI 草稿保存收到 409，按钮被禁用，重载后呈现最新 revision 2。旧草稿没有覆盖新策略。
- 重启隔离 DSH Desktop 并重新登录后，设置页仍显示该群 Enhanced、`qq.send: deny`、revision 2，OneBot 连接仍禁用。

## 安全边界与未完成项

管理 API 要求 DSH Connection 的 Owner admission 与同源请求；POST 还要求专用请求标记。localhost 本身不授予 Owner 权限。GUI 只显示 Scene 元数据，不展示聊天正文或凭据。`dsh.search`、QQ 媒体、QQ 空间和 Shell 当前是策略占位，不能以 UI 开关宣称已经可执行。

尚未验证真实 NapCat、平台投递、完整五级工具可见性、Owner Agent 通用 DSH 工具、Memory/State/Life 可信联动及跨 Scene 隐私。模拟 OneBot 和合成 Scene 不能代替这些验收。生产 QQ 保持断开。
